# AGENTS.md

Personal blog: `backend/` (FastAPI + SQLite) and `frontend/` (Vue 3 + Vite + Element Plus) are independent packages — no root workspace tooling. Frontend content is fully driven by backend data.

## Commands

- Backend: always via `uv run` (venv-local; `uvicorn` is NOT on PATH — use `uv run uvicorn app.main:app --reload --port 8000`).
  - Install: `cd backend && cp .env.example .env && uv sync`
  - Test: `uv run pytest` · Lint/format: `uv run ruff check app`, `uv run ruff format app`
- Frontend: `cd frontend && npm install`, then `npm run dev` (port 5173), `npm run build`.
- `npm run lint` / `npm run format` in package.json reference ESLint/Prettier that are **not installed** — don't run them unless you add the deps.
- Vite proxies `/api` and `/uploads` → `localhost:8000`, so no CORS setup needed for frontend dev.

## Backend architecture

- Entry `app/main.py`; layered as `core/` (config/security/logging/db) → `models/` → `crud/` → `api/v1/endpoints/`. Config is env-driven, prefix `BLOG_`.
- All responses use the envelope `{code, message, data}`. Auth: `POST /api/v1/auth/login`, `GET /api/v1/auth/me`; admin routes need `Authorization: Bearer <token>` (frontend stores it in localStorage `blog_token`).
- SQLAlchemy is async (aiosqlite). After `await db.commit()` objects are expired — `await db.refresh(post)` before serializing (see `get_post` in `posts.py`).
- Tables are auto-created + seeded on startup (admin user, default site configs). Alembic migrations live in `backend/migrations/` (`uv run alembic upgrade head`); both paths work because `create_all` is idempotent.
- On a fresh DB, startup also seeds demo content (6 categories with a parent/child hierarchy, 14 colored tags, 11 posts incl. 1 draft, 3 friend links, 2 banners) — only when the `posts` table is empty, so it's safe to re-run.
- When adding a model, import it in `app/models/__init__.py` — the class must be registered on `Base.metadata` or the table won't be created.
- Uploads: `POST /api/v1/admin/upload` stores into `backend/uploads/YYYY/MM/DD/` as `{YYYYMMDDHHMMSS}_{sha256[:8]}{ext}` (magic-bytes checked; svg allowed), registers a `media_assets` row, served at `/uploads` via StaticFiles (Vite proxies it in dev, nginx in Docker). `GET /admin/media` (paged, `dir=` prefix filter, `root` = legacy flat files, `deleted=true` = recycle bin only — everything else, incl. MediaPicker and folder counts, auto-excludes soft-deleted) / `GET /admin/media/folders` (per-dir counts for the tree) / `DELETE /admin/media` = SOFT delete (file stays on disk so public references keep working); `POST /admin/media/{id}/restore` (409 if the file vanished) and `DELETE /admin/media/{id}/permanent` = the reference-protected physical delete (`?force=true` bypass, migration `b7e2f4a9c3d1`); startup `sweep_existing_uploads` imports pre-library files once. Frontend must pick images through `components/admin/MediaPicker.vue` (local upload / library tabs) and never raw `el-upload` + URL inputs.
- Frontend theme: site config `site_accent_color` is applied to the CSS var `--blog-primary` via `stores/config.js`. Markdown rendering uses `md-editor-v3` (`MdEditor` in admin, `MdPreview`/`MdCatalog` on article pages), lazy-imported via `composables/useMdEditor.js`, which also registers the local `highlight.js/lib/common` + `screenfull` instances via `config()` (do NOT reintroduce `marked`).
- Frontend ordering: `useReveal.js` uses a `MutationObserver` to reveal async-rendered `.reveal` elements — don't "simplify" it back to mount-only observing or v-for sections stay invisible at `opacity: 0`.
- Post ordering (public list): `is_top` → `sort_weight` → `published_at` desc; category/tag order by `sort_order`. Categories/tags have a `visible` flag for homepage/tag-cloud display.
- Posts support **soft delete**: `deleted_at` column; admin delete moves to recycle bin (`GET /admin/posts?deleted=true`), restore = `POST /admin/posts/{id}/restore`, permanent = `DELETE /admin/posts/{id}/permanent`. Public lists, counts and stats all exclude soft-deleted posts — keep that filter when querying.
- Homepage category tabs are driven by `route.query.category_id` (single source of truth) so the nav menu and homepage stay in sync — don't reintroduce local-only tab state.
- Sidebar cards (`ProfileCard`/`HomeSidebar`) and the search panel are controlled by `site_*` config keys (see `seed.py` defaults); boolean configs arrive as strings ("true"/"false") — components must treat them as strings. Parse them only via `frontend/src/utils/config.js` (`isEnabled`/`toNumber`). The About page (`/about`) renders config `site_about_markdown` (rich Markdown, seeded with a sample template insert-if-missing, edited in a dedicated `关于我` tab of ConfigManage) via `MdPreview` and composes only existing public endpoints (stats/categories/tags/posts) — no dedicated table. Notices and social links moved to their own tables (no more `notice_*`/`profile_links` config keys).
- Navigation menus (`menu_items`): max **two levels** (enforced in `endpoints/menus.py`), the "首页" item is synthesized first by `GET /menus` and never stored; `type:'category'` must be top-level; legacy `site_menus` JSON migrates at startup (seed.py `_migrate_menus`, idempotent, invalid JSON = warn + skip); default menus are seeded into the table once (seed.py `_seed_default_menus`, config marker `menus_seeded` — never re-seeded after the user deletes them, and tests' lifespan may write this marker into the dev `data/blog.db`). Public tree must keep skipping hidden parents (with children) and the empty-table fallback — that's the config-breaks-but-site-lives guarantee. Header overflow collapsing lives in `composables/useNavOverflow.js` (clones the rendered nav DOM for widths, caches per item key in localStorage `blog_nav_item_widths`, first item never collapses).
- Notices (`notices`): `GET /notices` returns enabled ordered by `type, sort_order, id`; page-type content is nulled in the list (detail `GET /notices/{id}` has it, disabled → 404); PUT with changed title/content auto-bumps `version` — frontend dismissal memory is `blog_notice_dismissed:{id}` = version in localStorage (`utils/notice.js`).
- Annexes (`0.12.0`): RSS is `app/api/feed.py`, mounted at root `/feed.xml` AND `/api/v1/feed.xml` (hand-built xml string, no dep; the `/api/v1` copy is what Vite/nginx proxies reach). `GET /posts/archive` is declared **before** `/posts/{slug}` (path-param greedy) and the `archive_menu_added` config marker appends the 归档 menu row exactly once. `sidebar_notice_visible` (string bool) drives `HomeSidebar`'s notice card (page-type first, top 5). PostDetail throttles view counting with localStorage `blog_viewed:{slug}` (5 min → sends `?count_view=false`); reading time = CJK/400 per min + latin words/200.
- Social links (`social_links`): platform is a preset key or `custom` (with `label`); url must start with http(s):// or mailto:. Platform name/color/letter map lives in `frontend/src/utils/platforms.js`; nav icon registry lives in `frontend/src/utils/navIcons.js` (unknown icon names must render nothing, never throw).
- Config batch update (`PUT /admin/site/config`) validates whitelisted keys via `app/core/config_validation.py` — any invalid value rejects the whole batch with 422 before writing anything. Unknown keys pass through. `site_background` is enum-checked (`none/grid/aurora/dots/topo/geek/line`): CSS presets apply as `html[data-bg]` (styles/index.css on `body::before/::after`, z-index -1, transform-only animations, reduced-motion safe); `line` renders the `ParticleLines.vue` canvas (FrontLayout-only, visibility-paused); AdminLayout forces `data-bg="none"` on mount and restores on unmount.
- Admin UI (`0.12.1`): shared styles live in `frontend/src/styles/admin.css` (imported globally in `main.js`, all rules `.admin-layout`-scoped) — page toolbars use `.page-toolbar`, inline sort inputs use `.inline-sort` in 110px centered columns. Sort is inline-save everywhere (dialogs never PUT `sort_order` — they omit it on update). Element Plus dark CSS vars are imported globally; `AdminLayout` instantiates the theme store (applies saved theme on direct /admin loads) and hosts the light/dark switch.
- Batch ops (`0.13.0`): NO bulk endpoints — admin pages loop the existing single-item APIs per selected row via `utils/batch.js` (`runBatch`/`reportBatch`, silences per-item toasts during the loop) + `components/admin/BatchBar.vue`. PostManage adds batch category-move/publish/draft/trash (+ restore/permanent in recycle view); MediaManage trash ops; category/tag/friend batch visible; banner/notice batch enabled. `api/index.js` interceptor always toasts on failure — batch code must rely on `runBatch`'s aggregation, never per-item catch-and-toast.
- 0.14.0: social links carry optional `icon_url`/`color` (hex-validated in `endpoints/social.py`, migration `c9a1d2e3b4f5`) edited in a collapsible `.social-custom` sub-row in ConfigManage — keep them out of the main row. Config key `site_loading` (enum none/spinner/progress/bar, validated in `core/config_validation.py`) drives `components/PageLoading.vue` (mounted in `App.vue`) via `utils/loadingBus.js` — axios interceptors count in-flight requests (animation must track request activity, NOT router events, which fire before data arrives); min-display 400ms after last response; spinner mode adds a translucent overlay, bar/progress are top indicators. The mode must be a computed value, not a function. PostDetail meta is icon-chips; two hover-dropdown pills (fixed bottom-right, stacked above .back-top, el-dropdown top-end so menus open upward; mobile hides the tag span) switch 正文 previewTheme (6 built-ins shipped in preview.css) and 代码 hljs theme (localStorage `blog_post_preview_theme`/`blog_post_code_theme`) — hljs themes are local `?url` imports swapped through one `#hljs-theme-css` link (md-editor injects no hljs token css itself; multiple simultaneous hljs stylesheets would fight).
- Admin sidebar (0.15.0): `AdminLayout.vue` nav is a DEFAULT_NAV array (index/label/icon) rendered by el-menu; collapse (64px icon rail) persists to localStorage `blog_admin_collapse`, drag-sort mode writes the index-order array to `blog_admin_nav_order` (unknown/missing indexes auto-prune/append, clearing keys = default order). Sort mode re-keys the el-menu to flip its `router` prop off so drags don't navigate; every item needs its icon component or the collapsed rail shows blanks.
- Required fields (0.15.1): admin CRUD dialogs mark backend-required fields with Element `:rules` + `prop` (auto red asterisk, submit via `formRef.value.validate().catch(() => false)` guard, dialogs clear on `@closed`; MenuManage's path item is `v-if`-hidden for 栏目下拉 so its required rule is skipped). Site-config keys stay unmarked — the backend accepts empty values for all of them (defaults/fallbacks exist), don't invent frontend requirements. Social-link rows are plain divs (not el-form): URL red-star is the `.row-req` span in ConfigManage, validation stays in `validateSocialRows`.
- Site favicon: config key `site_favicon` is applied by `stores/config.js::applyFavicon()` inside `fetchConfig()` (both layouts call it, so admin/front share one icon); empty falls back to static `frontend/public/favicon.ico` (PNG-in-ICO, Vite copies it to dist root). Don't hardcode icon links elsewhere.
- Captcha: `GET /api/v1/auth/captcha` returns a PNG + `X-Captcha-Id` header; `POST /api/v1/auth/login` requires `captcha_id` + `captcha_code` fields. The backend skips captcha check when `captcha_id` is empty (backwards-compat for tests). The captcha store is an in-memory OrderedDict with a 5-minute TTL — not shared across workers.

## Gotchas (verified, do not "fix")

- `bcrypt` is pinned `<4.1` because passlib 1.7.4 crashes with bcrypt≥4.1 (72-byte password error at startup).
- `.env` sets a relative `sqlite+aiosqlite:///./data/blog.db`; `_resolve_sqlite_url()` in `core/database.py` rewrites it to an absolute path under `backend/`. Keep that rewrite — it makes the path cwd-independent.
- FastAPI/Starlette are very new (0.141/1.6): `TestClient` must be used as a context manager (`with TestClient(app)`) or the startup lifespan (table creation) never runs.
- Assigning an async-session relationship collection (`post.tags = [...]`) needs the old value preloaded or it lazy-loads synchronously → `MissingGreenlet` 500; `posts.py::_apply_tags` does `await db.refresh(post, attribute_names=["tags"])` first — keep that guard for any new relationship assignment.
- Alembic autogenerate renders FK adds that **fail on SQLite** ("No support for ALTER of constraints"); any new-column-with-FK migration must use `with op.batch_alter_table(...)` (see `43f81752c57c_category_hierarchy_colors_banners.py`).
- `StaticFiles(directory=...)` raises at import time if the dir doesn't exist — `main.py` `mkdir`s the upload dir before mounting.

## Testing

- `tests/conftest.py` overrides `get_db` with an in-memory SQLite engine (`StaticPool`). The app lifespan still seeds the real `data/blog.db` during tests, but the test admin/config are seeded manually in the `db_session` fixture — add any new seed data there too.
- `asyncio_mode = "auto"` is set; async fixtures/tests need no decorators.
- Run tests from `backend/`: `uv run pytest`.
